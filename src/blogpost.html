Python ABCs, Pattern Matching, and Runtime Types

A quick tour of what Abstract Base Classes can do in modern Python, why it is tempting to get clever with them, and why I usually do not.

TLDR: ABCs are great for semantics and documentation, but bending them to power match patterns and “negative types” gets cute fast and brittle faster. Prefer simple protocols or concrete predicates.

ABCs and structural checks

Python’s abc.ABC lets you define interfaces and, with __subclasshook__, treat classes as subtypes based on behavior instead of inheritance. That is powerful, especially for libraries that want to accept “anything iterable” or “anything that looks like a path”. 

from abc import ABC

class AbstractIterable(ABC):
    @classmethod
    def __subclasshook__(cls, C):
        return hasattr(C, "__iter__")

Pattern matching meets ABC

Since Python 3.10, match patterns can dispatch on types. That invites tricks like writing tiny ABCs purely to steer pattern matching. It works, but now your “types” exist only to satisfy a control-flow convenience. Maintenance pays the bill later. 

def visit(x):
    match x:
        case DistanceMetric():
            ...  # do A
        case Point():
            ...  # do B
        case _:
            ...

Combinators and negatypes

You can even generate ABCs at runtime to emulate boolean type combinators like Not, And, and Or. It is clever, and occasionally useful for experiments, but the indirection makes code harder to read, test, and refactor. 

def Not(cls):
    class _Not(ABC):
        @classmethod
        def __subclasshook__(_, C):
            return not issubclass(C, cls)
    return _Not

Why I avoid the cleverness

  • Readability: New contributors will not expect runtime-generated ABCs in a match.
  • Tooling: Type checkers and IDEs cannot reason about your bespoke ABC combinators.
  • Testing: Hidden subclass rules make fixtures and fakes surprising.
  • Drift: Over time the “type = behavior” contract gets fuzzy, which breaks invariants.

What I do instead

  • Use Protocols (typing) or simple duck-typing checks for behavior.
  • Prefer explicit predicate guards in match over fancy type routes.
  • Keep ABCs for stable, widely reused interfaces shared across modules.
